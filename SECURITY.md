# Security and sensitive reports

Please do not put personal data, credentials, private-account material, or unpublished indicators in a public issue or pull request.

- For a vulnerability in the viewer or tooling, use GitHub's private vulnerability reporting when it is enabled for this repository.
- For a record that contains excluded data, an identity error, or a legal-posture problem, use the [correction or removal form](.github/ISSUE_TEMPLATE/correction.yml). Write `private review requested` when the details should not be public.
- For source or dataset contributions, follow [CONTRIBUTING.md](CONTRIBUTING.md) and the [public-release checklist](RELEASE-CHECKLIST.md).

Do not contact a person named in the dataset. The project does not accept data obtained through contact, private accounts, active scanning, or credentialed access.
