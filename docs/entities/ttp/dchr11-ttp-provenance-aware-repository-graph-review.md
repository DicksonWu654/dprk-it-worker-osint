## Caveats

- Name similarity, profile images, avatars, code style, language, geography, account age, follower graphs, stars, forks, contribution volume and repository topic require corroboration before supporting legal identity, nationality, common operator or DPRK affiliation.
- Keep applicant messages, resumes, emails, phone numbers, identity documents, biometrics, private repositories, credentials, tokens, payment data, wallets, raw device or network selectors, active infrastructure and copied malware code out of the record.
- Accounts described by these sources remain unpublished, uncontacted, unfollowed, unstarred, unforked, unmessaged, and unprobed.
- Fake-interview malware remains analytically separate from fraudulent employment unless an exact source explicitly establishes overlap.
- Keep DPRK-linked fake-interview malware analytically separate from fraudulent employment unless an exact source establishes overlap.
- This source's account handles are withheld because they appeared active or ambiguously personal at publication time. Profile age, follower graphs, repository topics, language, geography, avatars and activity volume are review context rather than standalone classifiers.
- The record scope excludes person, persona, account, organization, repository, domain, contact value, executable code, active infrastructure selector, and applicant artifact.
- Researcher-attributed graph observations remain corroborative and review-only; attribution requires combined evidence.
- Researcher-attributed graph or dependency observations remain corroborative and review-only; they function as contextual signals rather than unique attribution.
- Retain the publisher-visible April 23, 2025 date; embedded WordPress metadata resolves to April 24 UTC, and automated date handling should preserve the publisher-visible date.
- Treat researcher and vendor attributions as claims with source, date, confidence, and limitation. Persona and account labels carry source-level identity status; civil identity is outside those labels.
- Use multiple independently explainable signals, trained human review, documented reasons, proportional collection, bounded retention, and a correction or appeal path.
- Verify exact package status and technical behavior independently before operational blocking; package-name similarity can create false positives.
